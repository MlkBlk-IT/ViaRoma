What is verified, in execution

  • The machine's IP never comes out — 5 automated levels of proof: fail-closed structure, curl_cffi transport, aiohttp transport, target ≠ proxy, IP absent from the repository, lanes and logs.
  • Credentials do not leak — never in a versioned file: they go in data/creds/ (git ignored), the YAML only carries a reference env: Or file:.
  • The waterfall burns the lane on 403/429 and keeps the account intact.
  • Each click of the dashboard triggers a real action — a mute click is a bug, not a design.

What is not demonstrated

  • A real completion : 1 adapter out of 15 validated against his forehead. The other 14 have a correct URL, payload and SSE parser, but never responded.
  • Anti-WAF bypass never worked against a real site.
  • No credential is provided : without data/creds/<account>.json, the cat returns a clean 503 — this is intentional.
  • Fronts web uniquement : no desktop/CLI support, and CI only tests code offline.
