Free Frontier Router

VIAROMA

Un MCP et une API OpenAI-compatible qui routent une requête vers un modèle frontier gratuit : cascade avec circuit breaker, egress IP jetable, sessions persistantes. Chaque clic du dashboard est une action réelle.
⛔ Alpha — ne pas utiliser 1 adapter validé sur 15

Fenêtre de contexte : la valeur réelle, ou « non publiée par la source » — jamais une valeur par défaut. Un ancien 32768 en dur sur 2 000 modèles a été supprimé ; chaque valeur porte sa provenance (ctx_source : métadonnées GGUF, OpenRouter, etc.).

Ce qui est vérifié, en exécution

  • L'IP de la machine ne sort jamais — 5 niveaux de preuve automatisés : structure fail-closed, transport curl_cffi, transport aiohttp, cible ≠ proxy, IP absente du dépôt, des lanes et des logs.
  • Les credentials ne fuient pas — jamais dans un fichier versionné : ils vont dans data/creds/ (gitignoré), le YAML ne porte qu'une référence env: ou file:.
  • La cascade brûle la lane sur 403/429 et garde le compte intact.
  • Chaque clic du dashboard déclenche une action réelle — un clic muet est un bug, pas un design.

Ce qui n'est pas démontré

  • Une complétion réelle : 1 adapter sur 15 validé contre son front. Les 14 autres ont une URL, un payload et un parser SSE corrects, mais n'ont jamais répondu.
  • Le contournement anti-WAF n'a jamais tourné contre un vrai site.
  • Aucun credential n'est fourni : sans data/creds/<compte>.json, le chat renvoie un 503 propre — c'est voulu.
  • Fronts web uniquement : pas de support desktop/CLI, et la CI ne teste que le code hors-ligne.
